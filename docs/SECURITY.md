# Security model

What this setup protects, how, and what it honestly cannot protect.

## The layers (strongest first)

### 1. proot-distro container — the hard boundary
Everything the agent does — opencode itself, every Bash tool call, every plugin,
every MCP server you wire — runs inside a proot Ubuntu userland. proot translates
syscalls in user space (no root involved). Without root on Android there is no
path out of that userland, and we deliberately do **not** bind-mount your Termux
home:

- `proot-distro login ubuntu` (as this repo does) mounts only the distro itself.
- Your `$HOME` in Termux, `/sdcard`, `/storage` and app data are invisible to
  everything running inside the container unless you later add a `--bind` /
  `--termux-home` flag yourself. **If file security is the point, never re-login
  with `--termux-home`.**
- Symmetric isolation: the phone's OS can't be scripted from inside either, and
  nothing you run inside can auto-start (no systemd, no init) — a compromise
  inside cannot persist across container sessions.

Windows/macOS-style OS sandboxes in opencode (Seatbelt/bubblewrap) are not
available on Android; the container *is* the sandbox. Treat a `--bind` to a
filesystem as the exact equivalent of disabling the whole security layer.

### 2. Permission profile (`opencode.json` → `permission`)
Written by the setup script (auditable copy: `templates/security-profile.json`):

- `bash` deny-list for world-breaking commands: `rm -rf /*`, `rm -rf ~*`, `dd …`,
  `mkfs*`, `chmod -R 777 …`, `shutdown`/`reboot`
- `external_directory: ask` — reading/writing anything outside the project
  directory requires you to tap approve (template/tmp dirs allowed)
- `share: "disabled"` — opencode cannot publish your session/prompts
- `autoupdate: false` — no silent binary replacement mid-flight
- `server.mdns: false` — no service broadcasting on LAN

Re-run freely to repair; explicitly customized permissions are never
overwritten (`SECURITY_PROFILE=secure` uses ??= semantics; `UNLOCK=1` does an
explicit overwrite; `SECURITY_PROFILE=keep` changes nothing).

### 3. Secret hygiene
- Model API keys live only in opencode's own auth store (`opencode` → `/connect`,
  saved to `auth.json` inside the container) — never in JSON you might commit.
- MCP keys go in `.env` (auto added to `.gitignore`) and are attached as request
  headers at startup. We do **not** put `{env:...}` substitutions into MCP URLs:
  Tavily URLs with URL-embedded env keys are known to break OpenCode's
  substitution, and keys hard-coded into config files end up in commits.
- `share` disabled + `.env` git-ignored means one-vector prompt exfiltration
  (model quoting your secrets into a shared/webfetched page) has fewer channels.

## What this does NOT fix (be honest with yourself)

- **Prompt injection is not solved.** A malicious page fetched via
  websearch/webfetch/MCP can still instruct your agent. The layers here reduce
  blast radius (container, external_directory ask, web-deny... they rely on
  you approving). Do not run `UNLOCK=1` on untrusted research sessions.
- **Outbound network is not restricted.** Anything inside the container can
  reach the internet. If that matters, add an on-device firewall policy or
  accept it — most code agents need network to be useful.
- **The proot boundary is syscall-translation, not a kernel sandbox.** Fine
  against accidents and shell mischief, not a hard guarantee against a
  dedicated, root-privileged attacker.
- **`UNLOCK=1` disables the seatbelt**, not the container. It is for
  twice-a-day trusted flows, not for "browse random archives" mode.
- Plugins run with your permissions. This setup pins the plugin list to names
  you chose at setup time, which is why the config is generated rather than
  hand-copied — re-run the script instead of trusting copy-paste snippets.

## Attack surface checklist (what would actually hurt)

| Vector | Layer that stops it |
| --- | --- |
| Agent runs `rm -rf ~/` | container (home not mounted) + deny-list |
| Agent edits files in Termux home | container (not mounted) |
| Agent sends your code to the web | permission `share: disabled`; network still open — see limits |
| Plugin does something sneaky | pinned plugin set generated by the script, defaults small |
| MCP leaks keys | `.env` outside git, headers, `share` off |
| Compromised container persists | nothing auto-starts; re-creating the userland resets it (`proot-distro remove ubuntu`) |

## If you want to start completely clean

```bash
proot-distro remove ubuntu   # from Termux: deletes the whole userland + agent + auth
```
Everything (auth.json, plugins) dies with it; nothing was on your Android side.
